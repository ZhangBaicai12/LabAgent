# 任务书：演示数据持久化 + 节点严格执行 + 机台 700 台

> 日期：2026-10-08 · 状态：待确认
> 范围：`frontend/` 静态演示升级为「本地可持久化运行」。不引入真实后端/数据库/鉴权。
> 依据：`system.md`（§五 已知缺口「演示版边界 · 数据不持久化」）、`WorkFlow.md`（业务基准）、`PFD/required.md`（生产机制方向，本任务取其「节点放行必须校验」精神的最小演示版 ）。

---

## 一、背景与目标

当前是纯静态演示：所有数据硬编码在 `frontend/data.js`，页面上的一切操作只改**内存**中的 `L.*`，刷新页面立即还原。做到以下几点后，演示才像「一个真的在用的系统」：

1. **数据落文件、改动即保存**：项目文件夹内一个数据文件，任何操作即时持久化，刷新/重开不掉状态。
2. **各节点严格按设定执行**：机台在某节点，必须完成该节点定义要求的事项（任务点、交付物、签名）才放行推进，不能跳节点、不能空提交。
3. **机台数据 700 台**：台账从 12 台扩到 700 台（含在建流转子集），页面可翻页/筛选，规模真实。

## 三、需求与方案

### R1 · 数据持久化（文件 + 及时保存）

**目标形态**：启动一个零依赖 Node 服务；项目文件夹里一个 `data/demo.json` 存全部演示数据；任何操作及时写盘。

**方案**：
- 新增 `server.js`（Node 内置 `http/fs/path`，**零 npm 依赖**）：
  - 静态托管 `frontend/`，演示入口改为 `http://localhost:8080/frontend/`（原 `file://` 直开不再作为演示入口，MANUAL 同步改启动方式）。
  - `GET  /api/data` 返回当前数据（读 `data/demo.json`）。
  - `POST /api/save` 原子写盘（写临时文件 + rename，避免写一半损坏）。
  - `GET  /api/reset` 重置为种子数据（演示「一键还原」）。
  - 首次启动 `data/demo.json` 不存在时，用种子生成器生成（含 700 台机台、28 台设备……）并落盘。
- 种子迁移：`data.js` 改造为**双出口种子模块** `data/seed.js`（同内容改尾端：`window.LAB` + `module.exports`）。
  - 服务端 `require` 它生成初始数据；浏览器端不再同步引用它（演示数据只能来自 `demo.json`，消除双源）。
- 前端改造：
  - `app.js` 改为：启动 `fetch('/api/data')` 载入 → 重建 `L` → `init()`（现有 IIFE 主体搬进 init 延迟执行；`rebuildRoles()` 等初始化调用随之移入）。
  - 新增统一提交钩子 **`commit()`**：业务动作处理函数（提交流转 / 退回/确认 / 更正 / 照片复核 / 台账新增 / 报告与工站入口 / 设备控制 / 定义与流程发布 / 脚本运行 / 数据源维护 等约十处）结尾调用 → 防抖 300ms → `POST /api/save` 全量快照。
  - 设备计时器（每秒 `runSeconds++`）**不做**每秒写盘：仅在看板停留期间的快照在卸载/切页时保存一次（`beforeunload` + hashchange 兜底）。
  - 顶栏加保存状态指示：「已保存 / 保存中… / 保存失败」。
- 严重性：所有弹窗/表单流程不变，只增加持久化层。

### R2 · 各节点严格按设定执行

**目标形态**：机台停留在某节点时，该节点 `STATION_DEFS` 定义要求的事项全部完成才放行推进；整批节点等整批；禁止跳节点；退回重做后该节点必做项必须重新完成方可再次提交。

**方案（全部从 `STATION_DEFS` 派生，不新增硬编码）**：
1. **推进源统一**：台账推进序改由「已发布节点列表」（按阶段 + `STAGE_STATUS_ORDER` 顺序）定位当前/下一节点，不再以裸 `TS_NEXT` 为唯一依据（`TS_NEXT` 收敛为「状态↔节点定位」的映射，不允许定义之外的状态跳转）。
2. **放行条件校验（提交时逐项检查，未满足列出缺项并拦截）**：
   | 校验维度 | 依据 | 规则 |
   |---|---|---|
   | 必做任务点 | 节点 `tasks[]`（upload/process/analyze/confirm/audit） | 该节点任务点全部达到完成态（节点作业卡逐个勾完），缺任何一项不放行 |
   | 交付物 | 节点 `outputs` → `ART_UPLOADS` | 本机台在该节点的产出交接物已登记，缺则提示「未登记产出：xxx」 |
   | 执行方式 | 节点 `exec` | `manual/semi`：必表单+签名；`auto`：自动钩子须已产出（或登记「已自动执行」） |
   | 责任人 | `owner`/有效责任解析 | 现有 `assertCan` 保留 |
   | 电子签名 | — | 保留现有签名区 |
   | 整批门闩 | `advance: 'batch'` | 同批/同工序其他机台未完成本节点前，提示「整批等待 x/y」，不单独放行 |
3. **顺序与重做**：提交只允许推进到定义序的下一节点；退回确认后机台回目标节点，该节点的必做项完成态清空、须重做再提交（`RETURNS` 流程保持现状语义）。
4. **缺项提示**：拦截时 toast + 节点作业卡上标红缺项，不静默。
5. 不改 `STATION_DEFS` 数据结构（字段够用）；不改「Agent 只读」介入边界。

### R3 · 机台数据 700 台

**目标形态**：机台台账 `MACHINES` 700 条（SN `MTL00001~MTL00700`，多型号 × 阶段分布 T0/TX/TF），`TRAVEL_SHEETS` 与之对应（其中在建流转子集若干、其余已完测/退库）。

**方案**：
- 在 `data/seed.js` 内新增**种子生成器**`genMachines(700)`：型号池（Falcon-2 / Falcon-2 Pro / Falcon-3 …）、阶段分布（如 T0≈350 / TX≈220 / TF≈130）、状态分布（在建若干 + 已完成 + 退库），生成后一次固化进 `demo.json`。
- 保留现有样例（MTL00011~22 及它们的时间线 / 报告 / Recon / 告警引用）作为叙事锚点；其余 688 台为「有模型 × 阶段 × 状态、精简结构」的记录。
- 在建子集控制在可演示规模（约 30~60 台处于各环节），其余为终态（done / done-no-tx），保证「总数 700、页面可翻（机台档案已有分页）可筛选、运行监控有真实量级」。
- 连锁同步：批次 `TEST_BATCHES / BATCH_MACHINES`、机台基础信息 `MACHINE_BASIC`、`KPI` 计数等与 700 台口径一致（沿用现有派生逻辑）。

### R4 · 设备看板落地（已定的 C 方案，顺带收尾）

- 设备数据扩到 28 台（同一批 Env 室/Cycle 室/充电架 设备、在线/离线/运行中 分布）。
- `#/devices` 改：「顶部统计带（总数/在线/离线/运行中）」+「紧凑设备卡片平铺网格」（现信息全字段 → 悬停 `title`），运行计时器/远程控制按钮/操作留痕保持不变。

## 四、边界（明确不做）

- 不做真实后端/数据库/登录鉴权/RBAC 服务端化（保持演示级，权限仍在前端）。
- 不做并发/事务/权限安全（单机演示）。
- 不做 PFD 里的编译器/LangGraph/调度等生产机制——只取其「放行必须校验」的最小语义。
- 不迁移真实数据、不接任何外部系统。
- 保留 `file://` 加载的旧种子直开方式不恢复（消除双源场景）。

## 五、实施顺序

1. **种子模块化**：`data.js` → `data/seed.js` 双出口；抽出 `genMachines(700)` / `genDevices(28)` 生成器。
2. **服务层**：`server.js`（静态托管 + `/api/data` `/api/save` `/api/reset` + 首次生成落盘）；补充 `.gitignore`（`.superpowers/`、`.DS_Store`）。
3. **前端持久化**：`app.js` 启动改 fetch 载入 + `commit()` 统一提交 + 顶栏保存指示 + 设备计时快照。
4. **节点严格化**：推进序派生 + 放行条件校验 + 整批门闩 + 缺项提示。
5. **规模与看板**：700 台机台 + 28 台设备种子；设备看板 C 方案渲染。
6. **文档与回归**：更新 `MANUAL.md`（启动方式/新特性）、`system.md`（缺口表去「数据不持久化」）；跑回归（详见验收）。

## 六、验收标准

- 启动：`node server.js` → 打开 `http://localhost:8080/frontend/`，首次生成 `data/demo.json`。
- 持久化：任一身份完成一笔业务动作（提交流转 / 复核 / 设备控制 / 退回 / 台账新增）→ 等防抖 → 文件内容变化 → **刷新页面状态保持**。
- 严格化：某机台在某节点缺必做项时提交被拦截并列出缺项；补全后放行；整批节点未满员不单独放行；不能跳节点。
- 规模：机台档案 700 台可翻页/筛选；各身份工作台/运行视图数字与 700 台口径一致；设备看板 28 台渲染且计时/控制正常。
- 回归：13 身份 × 24 路由无控制台报错、无 undefined/NaN；`node --check` 通过。
- `frontend/data.js` 移除浏览器侧直接引用；`MANUAL` 可指导教师复现演示与重置。
